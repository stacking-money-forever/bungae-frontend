## 1회 세션: 20–25분, 대상자 2–3명

진행자는 기기/계정·더미 모임을 준비하고, 참가자가 화면을 조작하도록 둔다. 시작 전에 “제품을 살펴보는 테스트이며 사람을 평가하지 않는다. 중단해도 불이익이 없다. 화면·발화 기록 여부를 선택할 수 있다”고 설명하고 동의를 받는다. 동의하지 않으면 녹화하지 않고 익명 메모만 남긴다. 전화번호·OTP·토큰·실명·음성 원본은 QA 기록에 남기지 않는다.

1. **발견·판단(4분):** “24시간 안에 참여할 만한 모임을 하나 찾아보고, 참가하기 전에 필요한 정보를 말해주세요.” 모임 찾기 경로, 시간·장소·정원·비용 확인, 결정 전에 남은 질문을 관찰한다.
2. **참가(4분):** “이 모임에 참여해 보세요.” 버튼을 찾는 시간, 누른 뒤 성공/대기 상태를 어떻게 해석하는지 기록한다. 진행자는 위치를 알려주거나 성공이라고 먼저 말하지 않는다.
3. **오류·재시도(4분):** **격리 환경에서만**, 테스트 담당자가 참가 요청 하나를 의도적으로 네트워크 중단하도록 사전 설정한다. “지금 화면을 보고 원하는 상태가 되도록 해보세요.” 오류 문구와 `같은 요청으로 다시 시도`를 어떻게 이해하는지 관찰한다. 이미 참가가 성립했거나 격리 실패 시 주입을 건너뛰고 이유를 적는다. 장애는 실제 백엔드 장애로 표기하지 않는다.
4. **재방문(3분):** “다른 화면에 갔다가 이 모임으로 돌아와 현재 참여 상태를 확인해 보세요.” `내 모임`과 상세 화면에서 상태가 일치한다고 느끼는지, 다시 참가해야 한다고 오해하는지 기록한다.
5. **참여 취소(3분):** “일정이 바뀌었습니다. 참가를 취소해 보세요.” `모임 참여 취소하기`를 찾고 결과를 설명할 수 있는지 관찰한다. 호스트의 `안전을 위해 모임 취소하기`와 혼동하는지도 확인한다.

막히면 60초간 침묵을 유지한 뒤 “지금 무엇을 기대하셨나요?”만 묻는다. 힌트를 주었다면 해당 단계는 **도움받음**으로 표시한다. 마지막 2–3분에는 “가장 헷갈린 순간은?”과 “참가/취소가 완료됐다고 어떻게 알았나요?”를 묻는다. 만족도 점수로 성공을 대체하지 않는다.
